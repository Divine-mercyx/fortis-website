Product

Fortis is continuous security testing for fintech teams. A CLI checks code before every push, staging checks run after every deploy, and every finding, fix and re-test becomes evidence for your pentester, partner banks and auditors.

No. Regulators still require a human third-party test, and people still find flaws tools miss. Fortis covers the releases in between, and gives your tester verified findings to start from.

Those are good general tools. Fortis focuses on fintech: payment-provider keys, ownership checks on money movement, webhook signatures, balance updates and BVN/NIN exposure. It adds staging access checks with your own test users, an evidence pack mapped to CBN and NDPA areas, and naira pricing.

The free checks work in any language. Secrets are found in any file, and dependencies are read for JavaScript, Python, PHP, Java, Kotlin, Scala, Go, .NET, Ruby, Rust, Dart/Flutter, Swift, Elixir, Haskell and R, plus Dockerfiles and GitHub Actions. The fintech code rules cover JavaScript, TypeScript, Python, Go, C#, PHP, Java and Kotlin.

The pre-push check only scans changed files, with a target of under ten seconds. Full-repository scans run in CI, where time matters less.

The CLI prints the rule, file, line and suggested fix. Fix it and push again. If it's a false positive, mark it with a reason; that decision is recorded as evidence and visible to your security lead.

Compliance

The pack maps findings, fixes and re-tests to CBN, NDPA and PCI DSS control areas. It's designed as input for your pentester, partner banks and auditors, not as a substitute for required tests. We're validating acceptance with design partners.
