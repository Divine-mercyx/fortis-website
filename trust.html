A security tool has to be safe first.

Vulnerability data is among the most sensitive information you hold. These are the rules Fortis is built on, and how we hold ourselves to them.

Principles

Six rules we don't break.

Your code stays with you

Analysis runs on your laptop or in your CI. Fortis never receives your source code.

Production is never attacked

Active checks run only on verified staging targets. Production is observed, never tested.

Only targets you verify

Prove ownership with a DNS record before any check, under a signed testing authorisation.

Signed releases

Signed packages with provenance, two-person release review and minimal dependencies.

Data hosted in Africa

Hosted in an Africa region by default, with Nigerian hosting for banks and larger MFBs.

NDPA-compliant processing

A data processing agreement for every customer under the Nigeria Data Protection Act 2023.

Exactly what we receive

This is a typical finding as sent by the CLI. Secret values are reduced to a fingerprint and the last four characters, so you can tell keys apart without exposing them.

  • Sent: rule ID, severity, file path, line number, masked snippet, commit hash.
  • Never sent: source files, full secret values, environment variables, customer data.
  • Offline mode: run the CLI with no network access and keep results local.

Safe active checks

Staging checks with guard rails.

Active checks send real requests, so they're the part of Fortis we restrict most. Every check needs all of these in place first.

  1. A signed testing authorisationYour organisation authorises Fortis to test named targets, in writing, before anything runs.
  2. DNS ownership proofA TXT record on the target domain. Change it and checks stop.
  3. Staging onlyTargets flagged as production are refused. Production is observed, never actively tested.
  4. Your own test usersChecks sign in as test accounts you create, with test data only.
  5. Read-only by defaultWrite checks are opt-in, per route, and rate-limited.
  6. Kill switchPause all checks for a target instantly from the dashboard or CLI.
Compliance

Mapped to the rules you answer to.

Fortis maps its findings and fixes to control areas, so your evidence speaks your reviewers' language. Mapping supports your compliance work; it isn't a certification.

CBN Risk-Based Cybersecurity Framework

Secure development, vulnerability management and testing through the software lifecycle, alongside an annual third-party test.

Nigeria Data Protection Act 2023

Security of processing for personal data such as BVN, NIN and account details. A DPA for every customer.

PCI DSS 4.0

Requirement 6 (secure software) and requirement 11 (security testing) control areas, for teams in card scope.
